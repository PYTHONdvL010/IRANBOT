# 🚀 معرفی

**IRANBOT** یک Telegram Shop برای فروش سرویس‌های VPN است که منطق فروش،
پرداخت، کیف پول، ساخت سرویس، پشتیبانی و مدیریت را در یک پروژه جمع می‌کند.

ساختار پروژه:

``` text
Telegram Bot
    │
    ├── محصولات
    ├── سفارش‌ها
    ├── کیف پول
    ├── پرداخت و رسید
    ├── سرویس‌های من
    ├── پشتیبانی
    ├── تست رایگان
    └── عضویت اجباری
            │
            ▼
       Web Admin Panel
            │
            ├── کاربران
            ├── محصولات
            ├── سفارش‌ها
            ├── پرداخت
            ├── پنل‌ها
            ├── Groupها
            ├── تست رایگان
            ├── خوش‌آمدگویی
            └── عضویت اجباری
            │
            ▼
   Marzban / Pasarguard / 3x-ui
```

# 🖥 پنل‌های پشتیبانی‌شده

پروژه برای سه نوع پنل آماده شده است:

  پنل              وضعیت
  ---------------- -------
  **Marzban**      ✅
  **Pasarguard**   ✅
  **3x-ui**        ✅

### Marzban / Pasarguard

ورود API با:

``` text
POST /api/admin/token
```

و استفاده از نام کاربری و رمز عبور پنل انجام می‌شود.

### 3x-ui

ورود از مسیر:

``` text
POST /login
```

و سپس بررسی وضعیت از API مربوط به پنل انجام می‌شود.

آدرس پنل قبل از استفاده پاک‌سازی می‌شود؛ بنابراین آدرس‌هایی مانند:

``` text
https://example.com/dashboard/#/
```

به Base URL مناسب تبدیل می‌شوند.

# 🔗 Pasarguard و Groupها

Pasarguard در این پروژه بر پایه ساختار زیر استفاده می‌شود:

``` text
User
  ↓
Group
  ↓
Inbound Tags
  ↓
Hosts
```

برای ساخت سرویس در Pasarguard:

1.  پنل را ثبت کنید.
2.  اتصال پنل را تست کنید.
3.  Groupهای قابل دسترس را دریافت کنید.
4.  Group موردنظر را ثبت کنید.
5.  در صورت نیاز چند Group را همزمان انتخاب کنید.
6.  محصول را به آن پنل متصل کنید.
7.  پس از پرداخت، سرویس بر اساس Groupهای ثبت‌شده ساخته می‌شود.

اگر API Group موقتاً خطا بدهد، برنامه باید خطا را به‌صورت قابل‌مشاهده نمایش
دهد و باعث Crash شدن Web Panel نشود.

### Subscription

اگر API پنل مقدار نسبی مانند:

``` text
/sub/xxxxxxxx
```

برگرداند، برنامه Base URL پنل را به آن اضافه می‌کند تا لینک کامل ساخته
شود:

``` text
https://panel.example.com/sub/xxxxxxxx
```

# 💳 پرداخت و کیف پول

## پرداخت مستقیم

روند پرداخت:

``` text
انتخاب محصول
    ↓
نمایش مبلغ دقیق
    ↓
نمایش شماره کارت و نام صاحب کارت
    ↓
ارسال رسید
    ↓
بررسی توسط ادمین
    ↓
تأیید
    ↓
ساخت سرویس
    ↓
ارسال Subscription
```

## کیف پول

کاربر می‌تواند کیف پول خود را شارژ کند.

در صفحه اصلی کیف پول اطلاعات کارت نمایش داده نمی‌شود.

اطلاعات کارت فقط هنگام پرداخت نمایش داده می‌شود:

``` text
💳 شماره کارت: ***************
👤 به نام: ***************
```

بعد از تأیید شارژ:

``` text
موجودی کیف پول += مبلغ تأییدشده
```

اگر موجودی برای خرید کافی باشد، سفارش می‌تواند بدون نیاز به رسید جدید از
کیف پول پرداخت شود.

# 👥 مدیریت کاربران

اطلاعات کاربران در جدول `users` ذخیره می‌شود.

اطلاعات اصلی:

``` text
user_id
username
first_name
is_blocked
created_at
last_seen
```

در مدیریت کاربران می‌توان:

-   کاربر را جستجو کرد.
-   اطلاعات کاربر را دید.
-   موجودی را مشاهده کرد.
-   موجودی را افزایش داد.
-   موجودی را کاهش داد.
-   کاربر را Block کرد.
-   کاربر را Unblock کرد.
-   وضعیت و اطلاعات پایه کاربر را بررسی کرد.

تعداد کاربران در Dashboard نیز نمایش داده می‌شود.

> نکته: اطلاعات حساس مثل Token ربات، رمز پنل‌ها و Secret نباید داخل
> README، GitHub یا فایل عمومی قرار بگیرد.

# 🔐 متغیرهای محیطی

این پروژه برای اجرای امن روی Railway از Environment Variables استفاده
می‌کند.

Railway متغیرهای تعریف‌شده را در زمان اجرای سرویس به‌عنوان Environment
Variable در اختیار برنامه قرار می‌دهد. citeturn0search0turn0search1

## متغیرهای اصلی

``` env
BOT_TOKEN=YOUR_TELEGRAM_BOT_TOKEN
ADMIN_IDS=123456789
DB_PATH=/app/data/shop.db
WEB_SECRET=CHANGE_THIS_TO_A_LONG_RANDOM_SECRET
PORT=8080
```

### `BOT_TOKEN`

توکن ربات Telegram.

مثال:

``` env
BOT_TOKEN=1234567890:AAxxxxxxxxxxxxxxxxxxxxxxxx
```

**توکن واقعی را داخل README یا GitHub قرار ندهید.**

### `ADMIN_IDS`

Telegram ID ادمین‌ها.

برای یک ادمین:

``` env
ADMIN_IDS=123456789
```

برای چند ادمین:

``` env
ADMIN_IDS=123456789,987654321,555555555
```

### `DB_PATH`

مسیر فایل SQLite:

``` env
DB_PATH=/app/data/shop.db
```

پیشنهاد می‌شود همین مسیر استفاده شود تا بتوان Volume را روی `/app/data`
قرار داد.

### `WEB_SECRET`

Secret مربوط به Session و ورود Web Panel:

``` env
WEB_SECRET=یک_رشته_تصادفی_طولانی_و_قوی
```

مثال:

``` env
WEB_SECRET=7f3c9e...long-random-secret...
```

اگر مقدار آن خالی باشد، برنامه در زمان اجرا Secret تصادفی تولید می‌کند؛
با این حال برای محیط Production بهتر است مقدار ثابت و امن در Railway
تنظیم شود.

### `PORT`

Railway مقدار `PORT` را در اختیار برنامه قرار می‌دهد و برنامه Web Panel
باید روی همان پورت گوش دهد. citeturn0search10

در این پروژه مقدار پیش‌فرض:

``` env
PORT=8080
```

است.

# 💾 Railway Volume

برای اینکه SQLite با Restart یا Deploy مجدد از بین نرود، پیشنهاد می‌شود
یک Volume بسازید و آن را روی:

``` text
/app/data
```

Mount کنید.

سپس:

``` env
DB_PATH=/app/data/shop.db
```

باشد.

> بدون Volume، فایل SQLite داخل filesystem سرویس قرار می‌گیرد و برای
> نگهداری دائمی اطلاعات Production گزینه مناسبی نیست.

# 🩺 رفع خطا و Troubleshooting

## خطای 500 در Web Panel

اول این موارد را بررسی کنید:

``` text
1. Railway Logs
2. BOT_TOKEN
3. ADMIN_IDS
4. DB_PATH
5. WEB_SECRET
6. Panel credentials
7. Panel API address
```

## خطا در Groupهای Pasarguard

بررسی کنید:

``` text
✓ پنل Pasarguard است
✓ Username / Password صحیح است
✓ آدرس Base URL صحیح است
✓ API قابل دسترسی است
✓ اکانت دسترسی لازم به Groupها را دارد
```

برخی حساب‌ها ممکن است به Endpoint کامل Group دسترسی نداشته باشند و فقط
Endpoint ساده را ببینند.

## Subscription با `/sub/...`

این حالت به‌تنهایی مشکل نیست.

برنامه Subscription نسبی را با Base URL پنل ترکیب می‌کند تا لینک کامل
ساخته شود.

## پرداخت تأیید شده ولی سرویس ساخته نشده

این موارد را بررسی کنید:

``` text
✓ Product فعال است
✓ Product به Panel متصل است
✓ Panel سالم است
✓ Pasarguard Group ثبت شده است
✓ API credentials صحیح هستند
```
